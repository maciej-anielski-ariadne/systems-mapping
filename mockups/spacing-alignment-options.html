Systematizing spacing & alignment — least to most disruptive

Same design language as the visual-consolidation work, now applied to space: make the 4px --space-* scale (already defined, currently unused) the single source of truth, fix the handful of real alignment defects, and offer a deliberate density choice. Previewed live below — pick a tier and the reproduced surfaces (chrome + map canvas) re-space in place; toggle ⇄ Split to compare against today, and ▦ 8px grid to see values snap onto the grid.

The ladder. ● T1 — Systematize: invisible; on-grid literals become identical tokens; fixes 3 real defects (panel-gutter mismatch, asymmetric canvas padding, a baseline). ● T2 — Consolidate: subtle; a few named control/card paddings, value columns share a right edge, the map canvas joins the same base unit. ● T3 — Density: opinionated; a one-token Calmer (more whitespace) or Compact (denser) preset.
Recommendation. Ship T1 now — it's invisible (on-grid values are byte-identical as tokens) and only corrects genuine defects. Follow with T2 (the value-column alignment + canvas-on-grid are the visible wins). Keep the default density; treat Calmer / Compact as a single opt-in token swap to decide later, not a prerequisite. Nothing here removes functionality.

01What the audit found

Measured across the 14 stylesheets and the JS layout config (02-config.js / 08-layout.js / 11-rendering.js), cross-checked by an adversarial reviewer. Today's real state.

The scale — defined but unused

The 4px scale has zero adoption unused
0 uses of --space-*

--space-1..6 (4/8/12/16/20/24) sit in 01-variables.css but every padding / gap / margin in the app is a raw px literal. Most are already on-grid, so the migration is mostly a no-visual-change find-and-replace.

Padding & gap sprawl ~40 combos

~40 distinct padding combos (incl. one-offs like 9px 14px 9px 36px), 11 gap values. Most are on-grid; the off-grid offenders:

579 111418 2226 4812 1624

6px is endemic & deliberate (dense rows + sidebar math) — legitimize as a --space-1_5 half-step, don't snap to 8.

Scattered vertical rhythm rhythm

margin-bottom ranges across 6 / 8 / 10 / 12 / 14 / 16 / 20 / 24px with no system — section, heading-to-body and list-item spacing all drift. Collapses to a 3-step rhythm (section 20, heading 12, item 8).

Alignment defects — the real bugs

The two panels don't share a gutter misalign

The left sidebar uses 20px side padding (04-sidebar.css:89); the right detail panel uses 24px (06-detail-panel.css:20). Content in the two panels starts at different insets. T1 unifies to 24.

Canvas padding is asymmetric canvas

SVG_PADDING = top 12 / right 24 / bottom 24 / left 24 (02-config.js:51-54). The map sits 12px from the top but 24px elsewhere. T1 makes it symmetric. Off-grid canvas metrics too: LABEL_INSET 14, NODE_LINE_STEP 13, COL_GAP 90, ROW_HEADER_WIDTH 110.

Ragged value columns tabular

Numeric readouts are now tabular (mono), but their containers use fixed off-grid widths 110 / 88 / 70 / 100px and flex auto-sizing, so the value right-edges don't line up across the detail / sim / edge rows. T2 gives them a shared right edge.

Half-pixel font sizes sub-pixel

Sizes 9.5 / 10.5 / 11.5 / 12.5px recur (counts, values, chips, edge meta) — they render on sub-pixel boundaries, softening text and nudging baselines. T1 snaps them (10.5→10, 12.5→12 …).

Labels overflow without truncating overflow

.sim-slider-name and .detail-edge-name are flex-shrink:0 with no ellipsis, so a long name pushes the value out of alignment — inconsistent with .outgoing-edge-target-link which does truncate. T2 standardizes truncation.

Builder header vs cell padding 2px

Table th uses 10px 10px but body cells use 6px 8px, so the column heads sit 2px off their column content. Plus a hand-tuned bottom toast stack (undo 22 / multi-select 72) that can collide on wrap.

One load-bearing constant to respect: NODE_HEIGHT = .panel-header height = --panel-strip-w = 44px. It's a deliberate "rhyme" across the canvas and the panels — so a density preset that changes NODE_HEIGHT (to 40 / 48) should move these together, not in isolation.
